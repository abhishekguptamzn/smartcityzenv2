## 1. Executive Summary & Vision

**Smart Cityzen** is an intelligent, unified digital gateway and physical access ecosystem designed to modernize civic and commercial spatial interaction. The application bridges residents, visitors, and space operators across municipal libraries, athletic facilities, fitness gyms, badminton courts, swimming academies, quiet co-working spaces, and city attractions.

The Flutter application (`smartcityzenv2`) serves as a dual-sided platform:
1. **Citizen Digital Passport & Wallet:** An intuitive consumer interface allowing citizens to explore verified civic spaces, book hourly slots or purchase recurring memberships, monitor real-time spatial crowd density ("Crowd Meter"), present secure dynamic cryptographic passes, check into venues via 0.2-second contactless scan, track attendance streaks, view digital tax invoices, and discover municipal cultural history.
2. **Facility Operator Console & Ambient IoT Gateway:** An integrated management suite enabling facility managers and staff to monitor live occupancy, validate member check-ins, process renewals, analyze revenue and fee plan distribution, broadcast notifications, answer citizen enquiries, and provision **Smart Edge IoT hardware nodes** via Bluetooth Low Energy (BLE) to mobile hotspot / Wi-Fi networks in under 5 seconds.

## 3. Toolchain Specifications, Version Rules & Solved Gotchas

The development environment has been hardened against known Flutter package conflicts. The following invariants must be preserved:

1. **Freezed 3.x Class Syntax:**
   All `@freezed` models MUST use `abstract class ModelName with _$ModelName`. Using `class ModelName with _$ModelName` (Freezed 2.x legacy style) causes silent inheritance failures and `non_abstract_class_inherits_abstract_member` compile errors under Dart 3.
2. **FormBuilder Intl Alignment:**
   `flutter_form_builder` must stay on `^10.3.0`+ to prevent version constraint clashes with `flutter_localizations` from the Flutter SDK.
3. **Analyzer & Linting Compatibility:**
   `analysis_options.yaml` contains `analyzer.errors.invalid_annotation_target: ignore`. This suppresses benign analyzer warnings generated by `@JsonKey(name: '...')` on Freezed constructor parameters. `custom_lint` and `riverpod_lint` were removed to prevent build_runner analyzer lockups.
4. **L10n Configuration:**
   `l10n.yaml` outputs to `lib/l10n/gen/` with class name `AppLocalizations`. `synthetic-package: false` is omitted to avoid deprecated option warnings.
5. **Secure Credential Redaction in Dio Logs:**
   In `lib/data/api/dio_client.dart`, debug logging scrubs sensitive payload keys (`password`, `password_confirmation`, `current_password`, `new_password`, `access_token`, `id_token`, `reset_token`, `token`) to ensure credentials are never exposed in debug logs.
6. **Reactive Dio Reconfiguration:**
   The `dioClientProvider` watches `appConfigControllerProvider`. When the user updates the API base URL or timeout settings in the runtime configuration, the Dio client automatically rebuilds its interceptors and base options without requiring an application restart.

## 7. Networking, Dio Interceptors & Security Architecture

The networking layer is implemented in `lib/data/api/dio_client.dart`:

```
┌─────────────────────────────────────────────────────────────┐
│                       Dio HTTP Client                       │
├──────────────────────────────┬──────────────────────────────┤
│ 1. Auth Header Interceptor   │ Injects `Bearer <sanctum>`   │
│                              │ from FlutterSecureStorage    │
├──────────────────────────────┼──────────────────────────────┤
│ 2. Redacted Logging Layer    │ Logs requests & responses    │
│                              │ while suppressing passwords, │
│                              │ auth tokens, & secret params │
├──────────────────────────────┼──────────────────────────────┤
│ 3. Typed Error Interceptor   │ Intercepts 4xx/5xx responses │
│                              │ and translates into typed    │
│                              │ `AppException` domain errors │
└──────────────────────────────┴──────────────────────────────┘
```

### 7.1 Error Mapping & Exceptions (`AppException`)
The API returns a standardized JSON envelope. The client maps server error codes to explicit typed exceptions:
* `VALIDATION_ERROR` (422) $\rightarrow$ `ValidationAppException` (carries per-field error maps).
* `AUTHENTICATION_ERROR` (401) $\rightarrow$ `UnauthenticatedAppException` (triggers automatic auth state invalidation and redirect to login).
* `AUTHORIZATION_ERROR` (403) / `ACCOUNT_BLOCKED` $\rightarrow$ `ForbiddenAppException`.
* `NOT_FOUND` (404) $\rightarrow$ `NotFoundAppException`.
* `TOO_MANY_REQUESTS` (429) $\rightarrow$ `RateLimitAppException` (initiates client-side cooldown timers).
* Network drop / Connection Timeout $\rightarrow$ `NetworkAppException`.

## 8. Complete API Endpoint Contract

The Flutter application connects to the `/api/v1` namespace (with `/api/health` for unversioned cluster checks):

### 8.1 Authentication & Profile Endpoints
* `POST /auth/register` — Register citizen account (Name, Email, Phone, City ID, Password).
* `POST /auth/login` — Authenticate via email & password.
* `POST /auth/oauth/{provider}` — Google / Facebook OAuth verification.
* `POST /auth/forgot-password` — Request password reset token.
* `POST /auth/reset-password` — Submit token and new password.
* `POST /auth/change-password` — Update password (throttled).
* `POST /auth/logout` & `POST /auth/logout-all` — Invalidate current or all device Sanctum tokens.
* `GET /auth/me` — Fetch current user profile.
* `PATCH /users/{id}` — Update user profile details.
* `GET /auth/login-history` — Retrieve paginated login history with suspicious IP flags.

### 8.2 Civic Facilities & Discovery
* `GET /cities` & `GET /cities/{id}` — Retrieve active cities, coordinates, and metadata.
* `GET /libraries` & `GET /libraries/{id}` — Search & fetch municipal library records.
* `GET /gyms` & `GET /gyms/{id}` — Search & fetch sports arenas and fitness centers.
* `GET /libraries/{id}/fee-plans` & `GET /gyms/{id}/fee-plans` — Retrieve pricing tiers.
* `GET /activities` & `GET /activities/{id}` — Search coaching batches, classes, and schedules.
* `POST /activities/{id}/enroll` — Submit enrollment request for activity programs.
* `POST /facilities/{id}/enquiry` — Send direct enquiry to facility administrators.

### 8.3 Check-in, Access & Attendance
* `POST /gyms/{gym_id}/attendance/check-in` — Contactless entry check-in via Member ID / Dynamic QR.
* `POST /gyms/{gym_id}/attendance/check-out` — Complete visit check-out session.
* `GET /gyms/{gym_id}/attendance/members/{member_id}/attendance` — Self-scoped attendance history.
* `GET /gyms/{gym_id}/attendance/{id}` — Check-in session detail.

### 8.4 Payments, Memberships & Tickets
* `GET /payments` — Self-scoped transaction history.
* `GET /payments/{id}` — Digital invoice and payment receipt detail.
* `GET /tickets` & `GET /tickets/{id}` — Civic support tickets and message thread.
* `POST /tickets` & `POST /tickets/{id}/reply` — Create support ticket and post replies.
* `GET /notifications` & `POST /notifications/{id}/read` — Citizen notification stream.

### 8.5 Facility Management Console (Staff / Operator Scoped)
* `GET /client/facilities` — Retrieve managed facilities assigned to staff/manager.
* `PATCH /client/facilities/{id}` — Update facility timings, capacity, description, amenities.
* `GET /client/facilities/{id}/members` — View active, expiring, and unpaid member rosters.
* `POST /client/facilities/{id}/members` — Manually register new venue member.
* `POST /client/facilities/{id}/members/{memberId}/renew` — Process membership renewal.
* `GET /client/facilities/{id}/attendance/today` — Live occupancy and today's attendance log.
* `POST /client/facilities/{id}/attendance/manual-checkin` — Manual override / check-in validation.
* `GET /client/facilities/{id}/reports/daily` — Daily check-in report.
* `GET /client/facilities/{id}/reports/monthly` — Monthly attendance trend report.
* `GET /client/facilities/{id}/reports/collections` — Revenue collection summary.
* `GET /client/facilities/{id}/reports/plans` — Fee plan popularity breakdown.
* `GET /client/facilities/{id}/enquiries` — Inbound citizen enquiries and reply dispatch.
* `POST /client/facilities/{id}/broadcast` — Send broadcast message to all facility members.

## 12. Build, Verification & Deployment Procedures

### 12.1 Code Generation & Static Analysis
To re-generate all Freezed models, JSON serializers, and Riverpod providers:
```bash
# 1. Fetch dependencies
flutter pub get

# 2. Generate localizations
flutter gen-l10n

# 3. Run build runner for Freezed & Riverpod
dart run build_runner build --delete-conflicting-outputs

# 4. Verify static analysis
flutter analyze
```

### 12.2 Running in Development
* **Web (Chrome):**
  ```bash
  flutter run -d chrome --dart-define=API_BASE_URL=https://smartct.online/api/v1
  ```
* **Android Device / Emulator:**
  ```bash
  flutter run -d android --dart-define=API_BASE_URL=https://smartct.online/api/v1
  ```

### 12.3 Generating Production Android APK / App Bundle
1. **Debug APK (For Testing & Sideloading):**
   ```bash
   flutter build apk --debug --dart-define=API_BASE_URL=https://smartct.online/api/v1
   # Output: build/app/outputs/flutter-apk/app-debug.apk
   ```
2. **Release APK (For Distribution):**
   ```bash
   flutter build apk --release --dart-define=API_BASE_URL=https://smartct.online/api/v1
   # Output: build/app/outputs/flutter-apk/app-release.apk
   ```
3. **Google Play App Bundle (.aab):**
   ```bash
   flutter build appbundle --release --dart-define=API_BASE_URL=https://smartct.online/api/v1
   # Output: build/app/outputs/bundle/release/app-release.aab
   ```
